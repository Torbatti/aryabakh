# پیشگفتار

## مفاهیم اولیه
1- هَمگَردار | Compiler:

در علم کامپیوتر به تابع یا مجموعه تابع هایی گفته میشود
که اعداد و حروف را دریافت میکند و اعدادی تولید میکند که برای کامپیوتر قابل خواندن باشد به اصلاح به زبان ماشین تبدیل میکند.
[^wikipedia:compiler]

2- تَرجُمار | Intrepreter:

در علم کامپیوتر به تابع یا مجموعه تابع هایی گفته میشود
که دو مسئولیت دارند 
اول اعداد و حروف را دریافت میکند و اعداد و حروفی تولید میکند که برای مفصر قابل خواندن باشد.
دوم به اعداد حروف تولید شده معنا میدهد تا بتواند آن را اجرا کند.
[^wikipedia:interpreter]

3- هَمگَردار لحظه ای | JIT Compiler:

دراین همگردار کد منبع برنامه در لحظه به کد قابل اجرای CPU تبدیل میشود و اجرا میشود.
[^wikipedia:jit]

4- نماینده میانه | Intermediate Representation :

نماینده میانه 
MIR (Medium Internal Representation) یا IR (Intermediate Representation)
به ساختار داده یا کدی گفته میشود که توسط همگردار ها و ماشین های مجازی سازی استفاده میشود تا کد منبع را بهینه سازی و به زبان های ماشین سطح پایین همگرداند. 
[^wikipedia:IR]


نمونه هایی از نماینده های میانی:

[WebAssembly](https://webassembly.org/)،
CPython ،
[LLVM IR](https://llvm.org/) ،
[MIR](https://github.com/vnmakarov/mir) ،
Go IR


## مقدمه 
همین حالا که شما این صفحه را مشاهده میکنید تَرجُمار و هَمگَردار 
مرورگر شما در حال اجرای جاوا اسکریپت میباشد. 
چیست و چرایی و چگونگی ترجمار و همگردار را بررسی میکنیم و سپس
یک ترجمار و همگرداری خواهیم نوشت و 
در هر مرحله انواع روش هایی برای آزمایش و یافتن خطاهای مختلف برنامه بررسی میکنیم.

## هدف ؛ ساخت ، آزمایش و خطایابی
*هدف اصلی* ،
آزمایش و خطایابی است چرا که هوش مصنوعی سرعت نوشتن برنامه را بسیار بالا برده است ولی نشانی از بهبود سطح عملکرد و امنیت در برنامه هایی که با هوش مصنوعی ساخته میشود دیده نمیشود و بلعکس برنامه های ساخت هوش مصنوعی پایداری و امنیت پایین تری برخردار هستند.

*هدف اصلی دیگر* ساخت ترجمار و همگردار است که پیچیدگی ترجمار و همگردار های بزرگتر را نداشته باشد ولی از ایده های اصلی آن ها استفاده بکند، تا آزمایش و خطایابی ما جلوه واقعی خود از دست ندهد و یک تئوری خالی نباشد.

*هدف نیست* : یادگیری برنامه نویسی و زبان برنامه نویسی.

# گفتار اول: ساخت ترجمار

## ترجمار چیست؟
ترجمار یک دستگاه برای دریافت اعداد ، حروف و نشانه هااست که آن ها را دسته بندی میکند و به آن ها معنا میدهد تا بتواند آن ها را بخواند و برنامه نهفته را اجرا کند.
در مرحله اول  ترجمار اعداد و حروف دریافت شده را میخواند و لغات مهم را از آن استخراج میکند.
در مرحله دوم  درخت گرامر از لغات استخراج شده ساخته میشود.
در مرحله سوم  به درخت مرحله سوم یا لغات مرحله دوم معنا میدهد تا بتواند آن را اجرا کند.
در مرحله چهارم  ، ترجمار دو راه را میتواند پیش بگیرد ؛ راه اول اجرای لغات معنا دار است ، و راه دوم تبدیل لغات معنادار به زبان اسمبلی و تبدیل آن به کد ماشین.
مرورگر های مدرن راه دوم را پیش میگیرند ، هر دو مورد را بررسی خواهیم کرد.
[^wikipedia:interpreter]

## چگونگی ترجمار
ترجماری که قرار است بنویسیم چگونه کار میکند؟

ترجمار شامل چهار بخش میشود که هرکدام حافظه مخصوص خود را دارند : بخش اجرا، برنامه، ورودی و خروجی.

بخش اجرا از طریق دستورات برنامه تغیر میابد و میتواند توسط ورودی جایگزین شود و یا به خروجی داده شود.

برای راحتی کار زبانی برای ترجمار اختراع میکنیم که برنامه را از آن طریق بنویسیم.

این زبان شامل هشت دستور میباشد.
`<` `>` `+` `-` `[` `]` `.` `,`

با دستور 
`,`
ورودی را دریافت میکند.

با دستور های 
`-` و `+`
حافظه ی هر خانه را کم یا زیاد میکند.

با دستور های 
`>` و `<`
به خانه بعدی یا قبلی میرود.

با دستور های
`]` و `[`
باعث تکرار دستورات میشود.

با دستور
`.`
جواب نهایی را خارج میکند.

## محدودیت های ترجمار
حافظه ی برنامه 30000 بایت است.
برای جلو گیری از حلقه بینهایت ، تعداد پرش ها باید محدود باشد معمولا ده به توان هفت پرش کافی است.
هر خانه حداکثر 255 و حداقل 0 است.
اگر به خانه ای که 255 است یک واحد اضافه شود به 0 برمیگردد.
اگر از خانه ای که 0 است یک واحد کم شود به 255 میرود.

## نوشتن ترجمار
حلقه ی برنامه:

در این مرحله خانه های برنامه را به ترتیب میخوانیم و دستورات آن را تا جایی که لازم است اجرا میکنیم.
بعد از هر بار خواندن دستور برنامه و عمل به دستور یک واحد اشاره گر برنامه را افزایش میدهیم و خانه بعدی برنامه را اجرا میکنیم
```c
while(1){
  switch(program[program_pos]){
    // محل قرار گیری دستورات برنامه اینجا است.
  }
  program_pos += 1;
}
```

دستورات `<` و `>` : 
اشاره گر خانه های اجرا را جابه جا میکند.
```c
case '<' : { 
  cells_pos = cells_pos - 1 ; 
} break;

case '>' : { 
  cells_pos = cells_pos + 1;
} break;
```

دستورات `+` و `-` : 
خانه های اجرا را کم و زیاد میکند.
```c
case '+' : { 
  cells[cells_pos] = cells[cells_pos] + 1;
} break;

case '-' : { 
  cells[cells_pos] = cells[cells_pos] - 1; 
} break;
```

دستورات `.` و `,` : به خانه ورودی میدهد یا خروجی را از خانه میگیرد.
```c
case '.' : { 
  output[output_pos] = cells[cells_pos];
  output_pos = output_pos + 1; 
} break;

case ',' : { 
  cells[cells_pos] = input[input_pos];
  input_pos = input_pos + 1; 
} break;
```
دستورات `[` و `]` :

`[`
اگر اول حلقه صفر باشد به آخر میرود و از حلقه خارج میشود. اگر اول حلقه صفر نباشد وارد حلقه میشود.

`]`
اگر آخر حلقه صفر باشد به از حلقه خارج میشود. اگر آخر حلقه صفر نباشد به اول حلقه میرود و وارد حلقه میشود.

```c
case '[' : {
  if (cells[cells_pos] != 0){ break; }

  int reached_bracket = 1;
  while (reached_bracket != 0)
  {
    program_pos = program_pos + 1;

    switch(program[program_pos])
    {
      case '[' : { reached_bracket = reached_bracket + 1; } break;
      case ']' : { reached_bracket = reached_bracket - 1; } break;
      default : break;
    }
  }
} break;

case ']' : {
  if (cells[cells_pos] == 0) { break; }

  int reached_bracket = 1;
  while (reached_bracket != 0)
  {
    program_pos = program_pos - 1;

    switch(program[program_pos])
    {
      case ']' : { reached_bracket = reached_bracket + 1; } break;
      case '[' : { reached_bracket = reached_bracket - 1; } break;
      default : break;
    }
  }
} break;
```

## همگردار لحظه ای چیست؟
همگردار لحظه ای یک دستگاه همگردار برای تبدیل متن برنامه به زبان ماشین سطح پایین تر در لحظه است.
[^wikipedia:jit]

همگردار لحظه ای دو مرحله دارد:
- مرحله اول: ساخت متن ماشین برنامه از متن برنامه در زمان اجرا
- مرحله دوم: اجرای متن برنامه در زمان اجرا
[^eli:jit:p1]

## چگونگی همگردار لحظه ای
همگردار لحظه ای در چهار مرحله کار میکند:

مرحله ابتدایی متن برنامه را به میخواند و تکه تکه میکند و تبدیل به یک درخت نحوی میکند.

در مرحله دوم (اختیاری) درخت بدست آمده را بهینه سازی میکند.

در مرحله سوم درخت را تبدیل به بایت هایی از جنس وب اسمبلی میکند.

در مرحله آخر بایت های وب اسمبلی را اجرا میکند.

## محدودیت های همگردار لحظه ای
صحت درست بودن برنامه را قبل را در زمان اجرا میفهمد.

کند شدن اجرای برنامه در اولین بار اجرا بخاطر تولید داده نماینده میانه.

# گفتار سوم: وب اسمبلی
## وب اسمبلی چیست؟
وب اسمبلی یک متن دودویی قابل حمل است که داخل یک ماشین مجازی اجرا میشود و محیط میزبانی آن 
بستگی به ماشینی که روی آن اجرا میشود تطبیق میابد.

## چرا وب اسمبلی؟
وب اسمبلی به خاطر قابل حمل بودن و سرعت نسبتا خوب در اجرای برنامه مورد استفاده قرار میگیرد.

## آزمایش و خطایابی و انواع آن
آزمایش یا خطایابی به عملی گفته میشود که در آن انتظارات ما (ایده آل) و واقعیت باهم روبرو میشوند.میزان نزدیکی واقعیت و انتظارات ما به کیفیت آزمایش ها بستگی دارد. از طریق آزمایش های درست تمام خطاها پیدا نمیشوند بلکه فقط قسمتی از خطاها پیدا میشوند .
زبان برنامه نویسی انتخابی شما میتواند از برخی گروه های خطا جلوگیری کند 
، به طور مثال اگر زبان برنامه نویسی انتخابی حافظه را بصورت خودکار مدیریت کند،
همچون زبان های گو ، جاوا و ... میتواند از گروهی خطرات و خطاهای مرتبط با حافظه جلوگیری کند . در عوض برنامه حافظه بیشتری مصرف میکند. 
در نظر داشته باشید که هر زبان برنامه نویسی مشکل ها و برتری های مخصوص خودش را دارد . 


## مستحکم سازی اولیه
قبل از آزمایش و خطایابی میتوانیم از ایجاد بسیاری از خطاها از طریق محدود سازی برنامه جلوگیری کنیم.

1- هر خانه حافظه باید اعداد 0 تا 255 را حداقل پشتیبانی کند. 

استفاده از نوع داده های زبان برنامه نویسی : `unsigned int`.

2- خانه ها اجازه منفی شدن یا بالا تر رفتن از 255 را ندارند.
```c
if(cells[cells_pos] > 255){ return -1; }
if(cells[cells_pos] < 0){ return -1; }
```

3- در زمانی که به خانه ها با مقدار 255 میخواهیم یک واحد اضافه کنیم باید آن را به 0 تبدیل کنیم.
```c
if(program[program_pos] == "-"){
  if(cells[cells_pos] == 0){ cells[cells_pos] = 255; }
  else{ cells[cells_pos] -= 1;}
}
```
4- در زمانی که از خانه ها با مقدار 0 میخواهیم یک واحد کم کنیم باید آن را به 255 تبدیل کنیم.
```c
if(program[program_pos] == "-"){
  if(cells[cells_pos] == 0){ cells[cells_pos] = 255; }
  else{ cells[cells_pos] -= 1;}
}
```

5- اشاره گر ها نمیتوانند کوچکتر از صفر یا بزگتر یا برابر با حداکثر طول بخش مورد نظرشان باشند.
```c
// @note: position SHOULD NOT be negative.
if(cells_pos < 0){ return -1; }
if(program_pos < 0){ return -1; }
if(input_pos < 0){ return -1; }
if(output_pos < 0){ return -1; }

// @note: MAX position = Max length - 1
if(cells_length <= cells_pos){ return -1; }
if(program_length <= program_pos){ return -1; }
if(input_length <= input_pos){ return -1; }
if(output_length <= output_pos){ return -1; }
```

6- طول بخش ها نمیتواند کوچکتر از 0 باشد.
```c
// @note: length SHOULD NOT be negative.
if(cells_length < 0){ return -1; }
if(program_length < 0){ return -1; }
if(input_length < 0){ return -1; }
if(output_length < 0){ return -1; }
```

## انواع آزمایش و خطایابی

آزمایش واحد `Unit Testing` : 
انتظار میرود هر بخش جداگانه به درستی کار کند .

آزمایش یکپارچگی `Integration Testing` :
انتظار میرود بخش ها یکپارچگی داشته باشند.

آزمایش مبدا به مقصد `E2E Testing` :
انتظار میرود بخش ها با یکدیگر از مبدا تا مقصد به درستی کار کنند.

آزمایش پسرفت `Regression Testing` :
انتظار میرود نسخه های جدید برنامه نسبت به نسخه قبلی بهینه تر یا بدون پسرفت باشد.
تمام تست های انجام شده را در دو نسخه جدا گانه زمان سنجی کنید و اختلاف را بررسی کنید.

آزمایش طلایی `Golden/Snapshot Testing` :
انتظار میرود حالات درست برنامه بدون تغیر در ادامه توسعه همانگونه کار بکنند.
خروجی برنامه سلام دنیا همیشه باید سلام دنیا باشد.

آزمایش فرضیات `Property-Based Testing` :
انتظاراتی که از سیستم میرود ولی گفته نمیشوند.
اگر به یک خانه یک واحد اضافه کنید ، مقدار خانه باید با مقدار قبل از اضافه کردن متفاوت باشد.

آزمایش حالت های خاص `Boundary/Edge Case Testing` :
انتظار میرود در حالت خاص به گونه ای کار کند که در حالت کلی اینگونه کار نمیکند.
اگر مقدار یک خانه کمتر از 0 و یا بیشتر از 255 شد برنامه باید متوقف شود.

آزمایش عملکردی `Performance/Benchmark Testing` :
انتظارات عملکردی نسبت به برنامه خود و برنامه رقبا بررسی میشود.

[^wikipedia:compiler]: wikipedia:Compiler [پیوند](https://en.wikipedia.org/wiki/Compiler)

In computing, a compiler is software that translates computer code written in one programming language (the source language) into another language (the target language). The name "compiler" is primarily used for programs that translate source code from a high-level programming language to a low-level programming language (e.g., assembly language, object code, or machine code) to create an executable program.


[^wikipedia:interpreter]: wikipedia:Interpreter (computing) [پیوند](https://en.wikipedia.org/wiki/Interpreter_(computing))

In computing, an interpreter is software that executes source code without first compiling it to machine code. An interpreted runtime environment differs from one that processes CPU-native executable code which requires translating source code before executing it. An interpreter may translate the source code to an intermediate format, such as bytecode.  

[^wikipedia:jit]: wikipedia:Just-in-time compilation [پیوند](https://en.wikipedia.org/wiki/Just-in-time_compilation)

Just-in-time (JIT) compilation (also dynamic translation or run-time compilations) is compilation of computer code during execution of a program at run time rather than before execution. This may consist of source code translation but is more commonly bytecode translation to machine code, which is then executed directly. A system implementing a JIT compiler typically continuously analyses the code being executed and identifies parts of the code where the speedup gained from compilation or recompilation would outweigh the overhead of compiling that code.

JIT compilation is a combination of the two traditional approaches to translation to machine code: ahead-of-time compilation (AOT), and interpretation, which combines some advantages and drawbacks of both. Roughly, JIT compilation combines the speed of compiled code with the flexibility of interpretation, with the overhead of an interpreter and the additional overhead of compiling and linking (not just interpreting). JIT compilation is a form of dynamic compilation, and allows adaptive optimization such as dynamic recompilation and microarchitecture-specific speedups.Interpretation and JIT compilation are particularly suited for dynamic programming languages, as the runtime system can handle late-bound data types and enforce security guarantees.

[^wikipedia:IR]: wikipedia: Intermediate representation [پیوند](https://en.wikipedia.org/wiki/Intermediate_representation)

An intermediate representation (IR) is the data structure or code used internally by a compiler or virtual machine to represent source code. An IR is designed to be conducive to further processing, such as optimization and translation. A "good" IR must be accurate – capable of representing the source code without loss of information – and independent of any particular source or target language. An IR may take one of several forms: an in-memory data structure, or a special tuple- or stack-based code readable by the program. In the latter case it is also called an intermediate language.

```c
// file: bf.c
#include "./bf.h"

#define NULL ((void *)0)

// @todo: make sure it works correctly on both big and small endian cpus
int bf_run(struct bf_state_machine *bfsm_ptr)
{
  // @todo: implement error types for bf_state_machine

  // @note: pointers SHOULD NOT be NULL.
  // @todo: check if pointer is invalid other than being NULL.
  // clang-format off
  if(bfsm_ptr->cells == NULL){ return -2; }
  if(bfsm_ptr->program == NULL) { return -3; }
  if(bfsm_ptr->input == NULL) { return -4; }
  if(bfsm_ptr->output == NULL) { return -5; }
  // clang-format on
  
  // @todo: prevent reading from input when input is null or empty string!
  while(1)
  {
    // @note: MAX position == Max length - 1
    // clang-format off
    if(bfsm_ptr->cells_pos >= bfsm_ptr->cells_length){ return -6; }
    if(bfsm_ptr->program_pos >= bfsm_ptr->program_length){ return -7; }
    if(bfsm_ptr->input_pos >= bfsm_ptr->input_length){ return -8; }
    if(bfsm_ptr->output_pos >= bfsm_ptr->output_length){ return -9; }
    // clang-format on

    // @note: increment steps_pos , if (steps_max == steps_pos) exit else continue
    // clang-format off
    bfsm_ptr->steps_pos = bfsm_ptr->steps_pos + 1;
    if(bfsm_ptr->steps_pos >= bfsm_ptr->steps_max){ break; }
    // clang-format on

    // clang-format off
    switch(bfsm_ptr->program[bfsm_ptr->program_pos])
    {
      // @note: move cells position to left
      case '<' : { 
        // @note: bounds check and returns an error before position reaches out of bound memory
        if(bfsm_ptr->cells_pos == 0){ return -10; }
        else{ bfsm_ptr->cells_pos = bfsm_ptr->cells_pos - 1 ; }
      } break;
      
      // @note: move cells position to right
      case '>' : { 
        // @note: bounds check and returns an error before position reaches out of bound memory
        if(bfsm_ptr->cells_pos == (bfsm_ptr->cells_length - 1)){ return -11; } 
        else{ bfsm_ptr->cells_pos = bfsm_ptr->cells_pos + 1; }
      } break;

      // @note: increment a cell by one
      case '+' : { 
        // @note: wrap around before increasing maximum value that can be an unsigned char
        if(bfsm_ptr->cells[bfsm_ptr->cells_pos] == 255){ bfsm_ptr->cells[bfsm_ptr->cells_pos] = 0; break; }
        else{ bfsm_ptr->cells[bfsm_ptr->cells_pos] = bfsm_ptr->cells[bfsm_ptr->cells_pos] + 1; }
      } break;

      // @note: decrement a cell by one
      case '-' : { 
        // @note: wrap around before decreasing minimum value that can be an unsigned char
        if(bfsm_ptr->cells[bfsm_ptr->cells_pos] == 0){ bfsm_ptr->cells[bfsm_ptr->cells_pos] = 255; break;  }
        else{ bfsm_ptr->cells[bfsm_ptr->cells_pos] = bfsm_ptr->cells[bfsm_ptr->cells_pos] - 1; }
      } break;

      // @note: loop starts if the value at cell position is not 0
      case '[' : {
        // @note: loop stops if the value at cell position is 0
        if (bfsm_ptr->cells[bfsm_ptr->cells_pos] != 0){ break; }

        // @note: skips the loop program if the value at cell position is 0
        int reached_bracket = 1;
        while (reached_bracket != 0) // @todo: this can turn into infinite loop on mistyped programs with one bracket. introduce maximum steps to prevent this from happening .
        {
          // @note: bounds check and returns an error before position reaches out of bound memory
          if(bfsm_ptr->program_pos >= (bfsm_ptr->program_length - 1) ){ return -12; }
          else{ bfsm_ptr->program_pos = bfsm_ptr->program_pos + 1; }

          switch(bfsm_ptr->program[bfsm_ptr->program_pos])
          {
            case '[' : { reached_bracket = reached_bracket + 1; } break;
            case ']' : { reached_bracket = reached_bracket - 1; } break;
            default : break;
          }
        }

        // @note: program_pos will get incremented at the end of loop

      } break;
      
      // @note: loop runs once more if the value at cell position is not 0
      case ']' : {
        // @note: loop stops if the value at cell position is 0
        if (bfsm_ptr->cells[bfsm_ptr->cells_pos] == 0) { break; }

        // @note: return to start of the loop program if the value at cell position is not 0
        int reached_bracket = 1;
        while (reached_bracket != 0) // @todo: this can turn into infinite loop on mistyped programs with one bracket. introduce maximum steps to prevent this from happening .
        {
          // @note: bounds check and returns an error before position reaches out of bound memory
          if(bfsm_ptr->program_pos == 0){ return -13; }
          else{ bfsm_ptr->program_pos = bfsm_ptr->program_pos - 1; }

          switch(bfsm_ptr->program[bfsm_ptr->program_pos])
          {
            case ']' : { reached_bracket = reached_bracket + 1; } break;
            case '[' : { reached_bracket = reached_bracket - 1; } break;
            default : break;
          }
        }

        // @note: program_pos will get incremented at the end of loop

      } break;

      // @note: copy data from cell position into output poistion
      case '.' : { 
        if(bfsm_ptr->output_pos >= bfsm_ptr->output_length){ return -14; }
        bfsm_ptr->output[bfsm_ptr->output_pos] = bfsm_ptr->cells[bfsm_ptr->cells_pos];
        bfsm_ptr->output_pos = bfsm_ptr->output_pos + 1; // @todo: this is dangrous! increasing position beyond length!
      } break;

      // @note: copy data from input position into cell position
      case ',' : { 
        if(bfsm_ptr->input_pos >= bfsm_ptr->input_length){ return -15; }
        bfsm_ptr->cells[bfsm_ptr->cells_pos] = bfsm_ptr->input[bfsm_ptr->input_pos];
        bfsm_ptr->input_pos = bfsm_ptr->input_pos + 1; // @todo: this is dangrous! increasing position beyond length!
      } break;

      default : break;
    }
    // clang-format on

    if(bfsm_ptr->program_pos == (bfsm_ptr->program_length - 1)){ break; }
    bfsm_ptr->program_pos = bfsm_ptr->program_pos + 1;
  }

  return 0;
}
```

```asm
;; bf.asm: Copyright (C) 1999-2001 by Brian Raiter, under the GNU
;; General Public License (version 2 or later). No warranty.
;;
;; To build:
;;nasm -f bin -o bf bf.asm && chmod +x bf
;; To use:
;;bf < foo.b > foo && chmod +x foo

BITS 32

;; This is the size of the data area supplied to compiled programs.

%define arraysize30000

;; For the compiler, the text segment is also the data segment. The
;; memory image of the compiler is inside the code buffer, and is
;; modified in place to become the memory image of the compiled
;; program. The area of memory that is the data segment for compiled
;; programs is not used by the compiler. The text and data segments of
;; compiled programs are really only different areas in a single
;; segment, from the system's point of view. Both the compiler and
;; compiled programs load the entire file contents into a single
;; memory segment which is both writable and executable.

%defineTEXTORG0x45E9B000
%defineDATAOFFSET0x2000
%defineDATAORG(TEXTORG + DATAOFFSET)

;; Here begins the file image.

orgTEXTORG

;; At the beginning of the text segment is the ELF header and the
;; program header table, the latter consisting of a single entry. The
;; two structures overlap for a space of eight bytes. Nearly all
;; unused fields in the structures are used to hold bits of code.

;; The beginning of the ELF header.

db0x7F, "ELF"; ehdr.e_ident

;; The top(s) of the main compiling loop. The loop jumps back to
;; different positions, depending on how many bytes to copy into the
;; code buffer. After doing that, esi is initialized to point to the
;; epilog code chunk, a copy of edi (the pointer to the end of the
;; code buffer) is saved in ebp, the high bytes of eax are reset to
;; zero (via the exchange with ebx), and then the next character of
;; input is retrieved.

emitputchar:addesi, byte (putchar - decchar) - 4
emitgetchar:lodsd
emit6bytes:movsd
emit2bytes:movsb
emit1byte:movsb
compile:leaesi, [byte ecx + epilog - filesize]
xchgeax, ebx
cmpeax, 0x00030002; ehdr.e_type (0x0002)
; ehdr.e_machine (0x0003)
movebp, edi; ehdr.e_version
jmpshort getchar

;; The entry point for the compiler (and compiled programs), and the
;; location of the program header table.

dd_start; ehdr.e_entry
ddproghdr - $$; ehdr.e_phoff

;; The last routine of the compiler, called when there is no more
;; input. The epilog code chunk is copied into the code buffer. The
;; text origin is popped off the stack into ecx, and subtracted from
;; edi to determine the size of the compiled program. This value is
;; stored in the program header table, and then is moved into edx.
;; The program then jumps to the putchar routine, which sends the
;; compiled program to stdout before falling through to the epilog
;; routine and exiting.

eof:movsd; ehdr.e_shoff
xchgeax, ecx
popecx
subedi, ecx; ehdr.e_flags
xchgeax, edi
stosd
xchgeax, edx
jmpshort putchar; ehdr.e_ehsize

;; 0x20 == the size of one program header table entry.

dw0x20; ehdr.e_phentsize

;; The beginning of the program header table. 1 == PT_LOAD, indicating
;; that the segment is to be loaded into memory.

proghdr:dd1; ehdr.e_phnum & phdr.p_type
; ehdr.e_shentsize
dd0; ehdr.e_shnum & phdr.p_offset
; ehdr.e_shstrndx

;; (Note that the next four bytes, in addition to containing the first
;; two instructions of the bracket routine, also comprise the memory
;; address of the text origin.)

db0; phdr.p_vaddr

;; The bracket routine emits code for the "[" instruction. This
;; instruction translates to a simple "jmp near", but the target of
;; the jump will not be known until the matching "]" is seen. The
;; routine thus outputs a random target, and pushes the location of
;; the target in the code buffer onto the stack.

bracket:moval, 0xE9
incebp
pushebp; phdr.p_paddr
stosd
jmpshort emit1byte

;; This is where the size of the executable file is stored in the
;; program header table. The compiler updates this value just before
;; it outputs the compiled program. This is the only field in the two
;; headers that differs between the compiler and its compiled
;; programs. (While the compiler is reading input, the first byte of
;; this field is also used as an input buffer.)

filesize:ddcompilersize; phdr.p_filesz

;; The size of the program in memory. This entry creates an area of
;; bytes, arraysize in size, all initialized to zero, starting at
;; DATAORG.

ddDATAOFFSET + arraysize; phdr.p_memsz

;; The code chunk for the "." instruction. eax is set to 4 to invoke
;; the write system call. ebx, the file handle to write to, is set to
;; 1 for stdout. ecx points to the buffer containing the bytes to
;; output, and edx equals the number of bytes to output. (Note that
;; the first byte of the first instruction, which is also the least
;; significant byte of the p_flags field, encodes to 0xB3. Having the
;; 2-bit set marks the memory containing the compiler, and its
;; compiled programs, as writeable.)

putchar:movbl, 1; phdr.p_flags
moval, 4
int0x80; phdr.p_align

;; The epilog code chunk. After restoring the initialized registers,
;; eax and ebx are both zero. eax is incremented to 1, so as to invoke
;; the exit system call. ebx specifies the process's return value.

epilog:popa
inceax
int0x80

;; The code chunks for the ">", "<", "+", and "-" instructions.

incptr:incecx
decptr:dececx
incchar:incbyte [ecx]
decchar:decbyte [ecx]

;; The main loop of the compiler continues here, by obtaining the next
;; character of input. This is also the code chunk for the ","
;; instruction. eax is set to 3 to invoke the read system call. ebx,
;; the file handle to read from, is set to 0 for stdin. ecx points to
;; a buffer to receive the bytes that are read, and edx equals the
;; number of bytes to read.

getchar:moval, 3
xorebx, ebx
int0x80

;; If eax is zero or negative, then there is no more input, and the
;; compiler proceeds to the eof routine.

oreax, eax
jleeof

;; Otherwise, esi is advanced four bytes (from the epilog code chunk
;; to the incptr code chunk), and the character read from the input is
;; stored in al, with the high bytes of eax reset to zero.

lodsd
moveax, [ecx]

;; The compiler compares the input character with ">" and "<". esi is
;; advanced to the next code chunk with each failed test.

cmpal, '>'
jzemit1byte
incesi
cmpal, '<'
jzemit1byte
incesi

;; The next four tests check for the characters "+", ",", "-", and
;; ".", respectively. These four characters are contiguous in ASCII,
;; and so are tested for by doing successive decrements of eax.

subal, '+'
jzemit2bytes
deceax
jzemitgetchar
incesi
incesi
deceax
jzemit2bytes
deceax
jzemitputchar

;; The remaining instructions, "[" and "]", have special routines for
;; emitting the proper code. (Note that the jump back to the main loop
;; is at the edge of the short-jump range. Routines below here
;; therefore use this jump as a relay to return to the main loop;
;; however, in order to use it correctly, the routines must be sure
;; that the zero flag is cleared at the time.)

cmpal, '[' - '.'
jzbracket
cmpal, ']' - '.'
relay:jnzcompile

;; The endbracket routine emits code for the "]" instruction, as well
;; as completing the code for the matching "[". The compiler first
;; emits "cmp dh, [ecx]" and the first two bytes of a "jnz near". The
;; location of the missing target in the code for the "[" instruction
;; is then retrieved from the stack, the correct target value is
;; computed and stored, and then the current instruction's jmp target
;; is computed and emitted.

endbracket:moveax, 0x850F313A
stosd
leaesi, [byte edi - 8]
popeax
subesi, eax
mov[eax], esi
subeax, edi
stosd
jmpshort relay

;; This is the entry point, for both the compiler and its compiled
;; programs. The shared initialization code sets eax and ebx to zero,
;; ecx to the beginning of the array that is the compiled programs's
;; data area, and edx to one. (This also clears the zero flag for the
;; relay jump below.) The registers are then saved on the stack, to be
;; restored at the very end.

_start:
xoreax, eax
xorebx, ebx
movecx, DATAORG
cdq
incedx
pusha

;; At this point, the compiler and its compiled programs diverge.
;; Although every compiled program includes all the code in this file
;; above this point, only the eleven bytes directly above are actually
```
